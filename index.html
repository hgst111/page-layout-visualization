CHAPTER 06 / VISUALIZATION

如何进行页面布局

Designing Page Layouts for Visualization

页面布局解决的，不只是元素放在哪里，而是信息关系应该以怎样的方式呈现给用户。

本章围绕同一个 Dashboard 案例，从一个数据和图表都没有明显问题、但页面关系混乱的状态出发，逐步建立更清晰的阅读路径。

01 / DIAGNOSE

先看到问题，再决定修改

诊断布局，意味着先观察页面关系，而不是立刻调整样式。

先不要修改它。先观察这个页面：图表本身是否有错？如果没有，为什么阅读体验依然不清晰？

EXPLANATION

把隐藏的空间关系显式化

Layout X-Ray 不是在评价页面好不好看，而是把模块边界、对齐、间距、分组和预期阅读顺序变成可以直接观察的证据。

Bounds 看模块边界；Alignment 看共同边缘；Spacing 看空白距离；Groups 看语义分组；Reading order 看预期阅读路径。

LAYOUT PRINCIPLES

布局并不是“摆整齐”这么简单

页面布局至少要同时关注对齐、间距与层级、分组、平衡和响应约束。本章把这些准则分别连接到可观察的实验：Alignment、Spacing、Balance / Allocation 与 Responsive Constraints 已展开，Hierarchy 与 Grouping 则连接到后续的分析图。

layout-xray.js JavaScript

读取真实模块的边界，把布局关系转成可以比较的坐标数据。

// 1. Measure the dashboard frame once.
const dashboardRect = dashboard.getBoundingClientRect();

// 2. Read each module's visible bounds.
const modules = [...dashboard.querySelectorAll("[data-module-id]")]
  .map((node) => {
    const rect = node.getBoundingClientRect();

    // Keep coordinates relative to the dashboard, not the viewport.
    return {
      id: node.dataset.moduleId,
      x: rect.left - dashboardRect.left,
      y: rect.top - dashboardRect.top,
      width: rect.width,
      height: rect.height
    };
  });

Why it matters：相对坐标把“看起来不齐”变成可以测量、比较的布局证据。

Initial Dashboard 的问题不是数据错误，而是模块之间的关系没有形成稳定的阅读顺序；下一步先判断哪些信息应该获得更多视觉显著性。

02 / HIERARCHY

让页面先回答“看什么”

视觉层级把内容的重要程度，转化成可被感知的差异。

视觉层级的目标不是让所有内容一样显眼，而是让重要信息获得合适的面积、位置或视觉显著性。布局出现问题时，常见的并不是图表错误，而是信息重要性与视觉显著性没有匹配。

下面的 Importance–Prominence Map 使用模块的语义重要程度和当前布局的可观察特征进行比较。Prominence 是一个透明的 layout prominence proxy：它不是眼动实验结果，也不是严格的人类视觉模型。

SEMANTIC IMPORTANCE 内容本身有多重要 由角色、任务和阅读目的决定。
LAYOUT PROMINENCE 页面让它有多显眼 由面积、位置和空间关系共同形成。

两者不一致时，问题不在于“重要性算错了”，而在于布局没有把判断结果转译成可感知的差异。

hierarchy-map.js JavaScript

用面积与垂直位置构造一个透明的 layout prominence proxy。

// Area is converted into a comparable visual signal.
const areaValue = Math.sqrt(rect.width * rect.height);
const areaScore = normalize(areaValue, minArea, maxArea);

// Earlier modules receive a small position advantage.
const positionScore = 1 - rect.y / layoutHeight;
const prominence = 1 + 9 * (
  0.65 * areaScore + 0.35 * positionScore
);

Why it matters：这个代理模型让“重要性”和“页面是否让它足够显眼”之间的差异可以被检查。

阅读提示：关注 areaScore 与 positionScore 如何共同影响显著性；它不是眼动预测。

教学代理模型：面积更大、位置更靠上，通常会形成更多布局显著性。这个简化公式用于让抽象概念可以被观察，不用于预测真实注意力。

    03 / GROUPING

    把信息关系变成空间关系

    靠近、分隔和对齐，会让相关信息自然形成一组。

    分组不是给每一个模块都加一个容器，而是让相关内容共享边界、节奏或起点。当空间关系足够清楚时，用户就不必依赖额外的说明文字来理解结构。

    本节把 Dashboard 的语义关系映射成 proximity、common region 和 alignment，再与真实页面中的空间距离进行比较。强关系如果在页面上相距很远，就可能形成值得检查的分组问题。

    Proximity相关内容靠近，减少寻找成本。
    Common region共享边界，提示属于同一组。
    Alignment共享起点或轴线，保持结构稳定。
    NOTE

    先决定哪些内容应该一起被阅读，再决定它们应该使用什么视觉样式。这里的距离阈值只服务于本教学案例，不是通用设计规则。

    文字可以列举关系，却不容易让人看出关系是否真的落在同一片空间里；下面的图把语义连线与真实距离并置起来。

    grouping-map.js JavaScript

    把两个模块中心之间的空间距离转成可检查的 proximity 信号。

    // Compare the centers of two related modules.
const dx = a.centerX - b.centerX;
const dy = a.centerY - b.centerY;
// Euclidean distance makes the relationship spatially explicit.
const distance = Math.hypot(dx, dy);

    Why it matters：中心距离提供了空间证据，但不会把“靠近”误当成唯一的语义判断。

    阅读提示：距离越大，不代表关系越弱；它说明语义关系与空间关系之间值得检查。

    04 / ALLOCATE

    为不同信息分配不同空间

    页面空间是一种有限资源，分配方式会直接表达优先级。

    先确定页面中必须被快速扫描的区域，再安排需要深入阅读的内容。宽度、留白和模块面积都可以成为一种无声的提示，帮助用户建立稳定的阅读路径。

    Treemap 在这里借用“把权重映射到有限矩形面积”的视觉思想，把页面看成一笔固定的空间预算。它是帮助我们观察分配关系的概念模型，不是网页自动布局算法；信息重要性越高，也不意味着它必须占据同等倍数的面积。

    01空间预算可用面积有限
    02视觉权重大小与位置传达优先级
    03阅读路径用户更快找到重点
    NOTE

    真实页面还要同时满足图表宽度、内容密度、控件固定空间和最小可读尺寸。Dashboard 的 filters 保持为顶部固定控制条，不进入主体面积分配。下面的 Importance influence 只是一个教学极端，用来观察当重要性逐渐影响面积时会发生什么。

    这条因果链说明了为什么“面积”不是单纯的美化参数；下面的代码和 Treemap 只负责呈现空间结果，权重仍然需要由设计者定义。

    allocation-map.js JavaScript

    混合当前占地与信息重要性，再把结果交给 Treemap 映射为空间。

    // Blend the current footprint with a design decision.
const weight =
  (1 - alpha) * currentWeight +
  alpha * importanceWeight;

// The hierarchy carries those weights into rectangular areas.
const root = d3.hierarchy(data)
  .sum(d => d.weight);

// Padding keeps neighboring semantic groups legible.
d3.treemap()
  .size([width, height])
  .paddingInner(8)(root);

    D3 负责把权重映射为空间，但权重如何定义仍然是设计决策。

    阅读提示：先看 weight 的来源，再看 size 与 padding 如何把判断转成面积和分组。

    05 / ADAPT

    让结构适应屏幕，而不是缩小一切

    响应式布局的重点，是保护信息关系在不同尺寸下仍然成立。

    当屏幕变窄时，布局需要重新做取舍：哪些内容保持并列，哪些内容转为纵向，哪些辅助信息可以暂时退后。好的适配会改变空间组织，但不会破坏页面的核心判断路径。

    Resize 是在相同拓扑中调整尺寸；Reflow 则是在可用空间不足时重新组织列数、顺序和分组。下面的 Responsive Viewport Lab 使用具体的教学阈值来演示这个过程，它们不是通用设备标准。

    RESIZE 结构不变，尺寸调整 同一组关系在更宽或更窄的空间中重新分配。
    REFLOW 结构改变，关系重组 当可读宽度不够时，列数、顺序或分组发生变化。
    NOTE

    响应式不是把固定画布整体缩小，而是让 available space 先改变，再由 readable width、信息关系和最低模块尺寸决定是否重组。

    layout.css CSS

    用 CSS Grid 表达常规桌面结构，并在可读宽度不足时切换为单列。

    /* Keep the desktop relationship side by side. */
.dashboard {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
}

/* Reflow when a module would become too narrow. */
@media (max-width: 760px) {
  .dashboard {
    grid-template-columns: 1fr;
  }
}

    CSS 负责真实网页的 reflow；本实验使用 D3 把 layout state 之间的变化过程可视化。

    阅读提示：这里的关键不是缩小所有模块，而是改变列关系来保护可读宽度。
    responsive-lab.js JavaScript

    根据 viewport 状态计算模块坐标，再把状态变化画成可观察的重排。

    // Compute a topology-aware layout for the current width.
const layout = computeLayout(viewportWidth);

// Only coordinates change; the module identities stay stable.
modules
  .attr("x", d => layout[d.id].x)
  .attr("y", d => layout[d.id].y);
    阅读提示：computeLayout 决定结构，D3 只负责把结构变化呈现出来。

    06 / SURGERY

    把原则放回一个完整案例

    综合重构，让诊断、层级、分组、空间与响应共同工作。

    最终的布局不是一组孤立技巧的叠加，而是一套相互支持的关系。我们会回到最初那个 Dashboard，保留数据和图表本身，重新安排它们出现的顺序、密度和空间位置。

    EXPLANATION

    重构的目标是减少解释成本

    当视觉层级和空间关系足够明确，用户可以把注意力留给数据本身。布局的完成，不是页面看起来更满，而是每一次停顿都有理由。

    01Observe先保留证据
    02Reframe重新判断关系
    03Recompose组织成可读结构
    layout-surgery.js JavaScript

    把前面形成的设计判断保存为不同 state，再用一次过渡展示重构过程。

    // The current step selects one measured layout state.
const state = surgeryStates[currentStep];

// Preserve module identity while moving its spatial properties.
modules
  .interrupt()
  .transition()
  .duration(600)
  .attr("x", d => state[d.id].x)
  .attr("y", d => state[d.id].y)
  .attr("width", d => state[d.id].width)
  .attr("height", d => state[d.id].height);

    前面的设计分析决定 target state，D3 负责把不同空间状态之间的变化可视化。

    阅读提示：变化的是位置和尺寸，不是数据；这正是布局重构的可视化过程。
